# Аудит DOS95 1.1.0

Дата: 2026-08-16

Ветка: `release/1.1.0`

Область: структура, исходный код, VFS, HTTP API, DOCTOR/OpenAI, зависимости, секреты, документация, тесты и Windows EXE.

## Итог

Критических и высоких нерешённых проблем не обнаружено. Подтверждённые структурные и security-проблемы исправлены. Релиз допускается как unsigned preview; для публичного production-распространения остаётся внешний блокер — доверенный Code Signing сертификат.

## Исправленные находки

| Уровень | Находка | Решение |
|---|---|---|
| Высокий | Изменяющий localhost API не имел process-token и строгой Origin/Host проверки | Добавлены 256-битный токен, точная проверка loopback/порта, CSP и rate limits |
| Высокий | DOCTOR полагался преимущественно на prompt модели | Добавлены локальные injection/crisis guardrails, input/output moderation, output leak filter и отсутствие tools |
| Средний | Тесты могли подхватить реальный `.env` | Провайдер явно отключён в integration/E2E среде |
| Средний | Состояние VFS не было долговечным и атомарным | Добавлены persistent storage, backup/restore и тесты повреждения |
| Средний | Устаревший Explorer и документация описывали отсутствующие файлы | Мёртвый fallback удалён, документы консолидированы, legacy сохранён отдельно |
| Низкий | `HELP`/`VER` показывали жёстко заданную старую версию | Версия читается из `package.json` |
| Средний | Успешный ответ API показывался как ошибка связи из-за отсутствующего `status-mode` в Win95 | DOM-элементы сделаны optional, сетевые и UI-ошибки разделены, добавлена E2E-регрессия |
| Средний | Корневой маршрут обходил задуманную загрузку DOS → Windows 95 | `/` возвращён к DOS, команда `WIN95` выполняет same-tab переход, общая VFS проверяется E2E |
| Средний | Повторный запуск ELSA создавал окна с одинаковым ID и оставлял неуправляемый экземпляр | ELSA сделана однооконной, исправлены focus/minimize/close и изоляция асинхронного сеанса |
| Низкий | Не была закреплена политика line endings и исключения сертификатов | Добавлены `.gitattributes`, `*.pfx` и `*.p12` в `.gitignore` |

## Зависимости и секреты

- `npm audit` и `npm audit --omit=dev`: 0 известных уязвимостей.
- Direct dependencies установлены в закреплённых версиях; Express 5 и dotenv 17 являются major upgrades и сознательно не включены в security-релиз без отдельной миграции.
- `.env`, `node_modules`, `dist`, coverage, IDE-файлы и приватные контейнеры сертификатов игнорируются Git.
- Поиск key-shaped значений в рабочем дереве и всей Git-истории не обнаружил реального API-ключа. Совпадения относятся к placeholders и тестам.
- OpenAI SDK вызывается только сервером; browser bundle не содержит ключа.

## Принятые ограничения

- Prompt-injection и moderation guardrails снижают риск, но не дают математической гарантии для всех будущих атак.
- Другой процесс с правами того же пользователя потенциально может обращаться к loopback и читать память/трафик пользователя; process-token прежде всего защищает browser boundary.
- CSP сохраняет `unsafe-inline` для стилей существующего интерфейса, но inline scripts запрещены.
- Антивирусное сканирование и Authenticode подтверждают разные свойства и не заменяют review исходного кода.
