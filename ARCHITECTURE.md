# Архитектура DOS95

## Поток выполнения

```text
Браузер (Windows 95 / DOS)
          |
          | JSON API, same-origin + process token
          v
Express на 127.0.0.1
   |             |
   v             v
CommandHandler   File API
   |             |
   +------> VirtualFileSystem
                    |
                    v
          %LOCALAPPDATA%\DOS95\vfs.json
```

## Компоненты

- `server.js` создаёт приложение, ограниченные сессии и локальный HTTP-сервер. Статические пути разрешаются от `__dirname`, поэтому запуск не зависит от текущего каталога.
- `filesystem/virtualFS.js` владеет моделью диска `C:`. Все пути нормализуются, операции возвращают реальный результат, перемещение выполняется без потери источника при ошибке.
- `filesystem/storage.js` сохраняет общее состояние VFS атомарно через временный файл. Повреждённый JSON переименовывается, после чего загружается исходное состояние.
- `commands/handler.js` разбирает кавычки, алиасы и перенаправление вывода. Файловые и системные команды разделены по модулям.
- `commands/doctorSecurity.js` нормализует и ограничивает сообщения, отсекает явные prompt injection и кризисные формулировки, фильтрует ответы и ограничивает историю.
- `commands/doctorCommand.js` использует Responses API, входную/выходную модерацию, разрешённый список моделей, `store: false` и стабильный псевдонимный `safety_identifier`. Модели не передаются инструменты. При отсутствии сети или ключа отвечает локальная ELIZA.
- `filesystem/instanceIdentity.js` хранит локальный случайный идентификатор экземпляра и передаёт провайдеру только его SHA-256 хеш.
- `public/api-client.js` получает одноразовый токен текущего процесса и добавляет его ко всем изменяющим API-запросам.
- `public/explorer-enhanced.js` работает через структурированный файловый API. Пользовательский текст вставляется через DOM `textContent`, а редактор сохраняет содержимое без преобразования через `ECHO`.

## API

- `POST /api/command` — `{ command, sessionId }`;
- `POST /api/file` — операции `list`, `read`, `create`, `write`, `copy`, `move`, `delete`, `mkdir`, `rmdir`;
- `GET /api/bootstrap` — выдаёт браузеру токен текущего локального процесса с запретом кеширования;
- `GET /api/commands`, `/api/health`, `/api/runtime`;
- `POST /api/shutdown` — доступен только автономному процессу и требует общий токен приложения.

Сервер слушает только IPv4 loopback, сверяет Host, порт и Origin, применяет CSP/защитные HTTP-заголовки и rate limits. Все изменяющие запросы требуют случайный токен процесса. Состояние диска общее и долговечное, а текущий каталог, история команд и режим `DOCTOR` принадлежат отдельной сессии.

## Проверки

- Node test runner: VFS, persistence, parser, команды и HTTP API;
- встроенное покрытие Node: минимум 85% строк/функций и 75% ветвей;
- Playwright Chromium: терминал, Проводник, точное round-trip сохранение текста и блокировка prompt injection;
- EXE smoke: запуск без Node.js в `PATH`, авторизация API, общая VFS, guardrails и shutdown.

## Дистрибуция

`@yao-pkg/pkg` создаёт Windows x64 Enhanced SEA с Node.js 24 и встроенными ресурсами `public`. Результат не требует установки среды выполнения. Файл `.env` остаётся внешним рядом с EXE, поэтому секреты не встраиваются в бинарник.
