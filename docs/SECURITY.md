# Модель безопасности DOS95

## Границы доверия

DOS95 — локальное веб-приложение. Доверенными считаются только код установленной сборки и локальное состояние приложения. Команды, имена файлов, содержимое VFS, сообщения DOCTOR, HTTP-заголовки и ответы внешнего провайдера обрабатываются как недоверенные данные.

VFS изолирована на уровне логики приложения, но DOS95 не является системной песочницей. EXE и Node.js-процесс имеют обычные права текущего пользователя, поэтому запускайте только сборку с проверенным хешем и подписью.

## Локальный HTTP-сервер

- привязка только к `127.0.0.1`, без LAN-доступа;
- точная проверка Host/порта и Origin;
- случайный 256-битный токен процесса для всех изменяющих запросов;
- CSP, `nosniff`, запрет framing и referrer policy через Helmet;
- лимиты JSON, сессий, истории и запросов;
- generic-сообщения для внутренних ошибок;
- shutdown разрешён только автономному процессу.

Токен защищает от случайных и межсайтовых запросов, но не от другого вредоносного процесса, уже выполняющегося с правами того же пользователя.

## DOCTOR и OpenAI

Локальные guardrails выполняются до обращения к провайдеру:

- NFKC-нормализация, удаление zero-width символов и контроль длины;
- блокировка явных попыток смены роли, раскрытия prompt/API key, fake-role тегов, запуска shell и простого кодирования инструкций;
- отдельный безопасный ответ для кризисных формулировок;
- входная и выходная модерация `omni-moderation-latest`;
- разрешённый список `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.6-sol`;
- Responses API без tools, `store: false`, максимум 300 output tokens;
- ограниченная история и псевдонимный SHA-256 `safety_identifier`;
- фильтрация ответа на признаки ключа или системной конфигурации;
- безопасный fallback на локальную ELIZA.

Эвристические фильтры и инструкции модели не могут гарантировать защиту от каждой будущей prompt injection. Не передавайте пароли, ключи, платёжные данные или медицинские документы.

## Секреты и файлы

`OPENAI_API_KEY` читается сервером из `.env` рядом с исходным `server.js` или EXE. Ключ не встраивается в бинарник и не возвращается браузеру. `.env`, `*.pfx`, `*.p12`, `dist`, `node_modules` и данные VFS не отслеживаются Git.

При компрометации ключ нужно отозвать у провайдера и создать новый. Удаление строки из Git или `.env` не отзывает ключ.

## Известные ограничения

- Текущий локальный EXE не имеет доверенной цифровой подписи до предоставления Code Signing сертификата.
- CSP разрешает inline styles для существующего ретро-интерфейса, но запрещает inline scripts.
- DOS95 не выполняет антивирусное сканирование пользовательского компьютера.
- Локальная ELIZA не использует модель или модерацию провайдера, но локальные injection/crisis guardrails продолжают работать.

Сообщения об уязвимостях следует передавать владельцу репозитория приватным каналом, не публикуя ключи или рабочий exploit в открытой issue.
